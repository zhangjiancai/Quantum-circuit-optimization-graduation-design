## 1. 30 秒电梯陈述

> 这个课题把“量子电路的等价重写优化”建模成强化学习问题：状态是电路的门-比特-时隙张量，
> 动作是 4 类保持语义不变的局部重写规则，用带动作掩码的 CNN Actor-Critic 网络和 PPO 学习
> “在什么位置执行哪条规则”，奖励设计成“每一步相对初始代价的压缩比例”。
> 原仓库的代码在状态编码、奖励、掩码、PPO 概率计算和训练脚本上都有致命错误，我把它重写成
> 了一个能训练、能评估、可复现、且每条规则都用幺正矩阵验证语义等价的完整工程。

## 2. 一页纸核心（只记这些）

### 2.1 一句话

**用 PPO 学一个“在哪执行哪条等价重写规则”的策略，在保证电路幺正等价的前提下降低 门数 + λ·深度。**

### 2.2 必背的 10 个点

1. **问题**：语义保持的电路重写优化 = 带约束的组合优化；用 RL 学启发式策略。
2. **状态**：`[C=14, Q=5, M=15]` 张量；11 个门通道 + control + target + idle。
3. **动作**：`(规则 r, 比特 q, 时隙 m)`，共 `4×5×15=300` 个；`index=(r*Q+q)*M+m`。
4. **4 条规则**：合并单比特门（merge）、抵消自逆二比特门（cancel）、门前移（move_earlier）、门后移（move_later）。
5. **掩码**：`mask[r,q,m]` 只在规则适用且 `m<depth` 时为真；非法动作概率严格 0。
6. **奖励**：`r_t=(C_t−C_{t+1})/C_0`，`C=门数+0.5×深度`；每步为正，总（未折扣）回报 = 代价压缩比例。
7. **网络**：3 层 3×3 卷积共享主干（ELU，无 BatchNorm）→ 策略头 1×1 卷积（logits）+ 价值头（→128→1）。
8. **PPO**：GAE（含最后一步 + bootstrap）+ 裁剪目标 + 价值 MSE + 熵正则 + 小批量多轮 + KL 早停 + 梯度裁剪。
9. **正确性**：每条规则应用后 `cost` 严格下降且 `circuits_equivalent` 为真；测试 200 电路 × 4 规则；评估等价率 = 1.0。
10. **原仓库核心错误**：规则在加门、状态时隙索引错、掩码恒真、双重 softmax、GAE 漏最后一步、train 切片错 + 吞异常、data_generator 调不存在 API。

### 2.3 公式卡

```
代价            C = num_ops + λ·depth,  λ = 0.5
动作编码        index = (r·Q + q)·M + m
状态形状        s ∈ R^{14×Q×M}
奖励            r_t = (C_t − C_{t+1}) / C_0
GAE             δ_t = r_t + γV(s_{t+1})(1−d_t) − V(s_t)
                A_t = δ_t + γλ(1−d_t)A_{t+1}
                returns = A + V
PPO ratio       ρ_t = exp(logπ_new − logπ_old)
策略损失        L = −E[min(ρA, clip(ρ,1−ε,1+ε)A)]
总损失          L = −L_clip + 0.5·MSE(V,R) − 0.01·H[π]
```

| 项 | 值 |
| --- | --- |
| 比特数 / 时隙窗口 / 初始深度 | 5 / 15 / 12 |
| 动作空间大小 | 300 |
| 观测张量 | 14×5×15 |

## 3. 3 分钟口头陈述稿

> 各位老师好，我的课题是“基于强化学习的量子电路等价重写优化”。
>
> 量子电路在编译阶段可以做很多等价变换来减少门数和深度，比如把相邻的两个单比特门乘起来、
> 把连续两个相同的 CNOT 消掉、把独占一层的门前移或后移来压缩深度。问题在于：在什么位置、
> 用哪条规则，组合起来空间很大，人工启发式不一定最优，所以我把这件事建模成马尔可夫决策过程，
> 用强化学习学一个策略。
>
> 具体来说，状态是电路的门-比特-时隙张量，14 个通道分别编码 11 种门、二比特门的控制/目标
> 比特和空闲位置；动作是“规则、比特、时隙”三元组，一共 300 个；只有当前真正可用的动作才会
> 被动作掩码放行。奖励定义为每一步相对初始代价的压缩比例，这样每走一步奖励都为正，
> 回合总回报正好等于“电路代价压缩了多少”。网络是共享卷积主干的 Actor-Critic，策略头输出每个
> 动作的 logits，价值头估计状态价值；训练用 PPO，包含 GAE、裁剪目标、熵正则、KL 早停和梯度裁剪。
>
> 这个课题真正的难点不在算法，而在于“正确性”。原仓库的代码存在一系列问题：它的“规则”其实是在
> 往电路里加门，语义会变；状态张量把所有门写到同一个错误的时隙；动作掩码永远返回全 True；
> 策略网络先做 softmax，采样时又归一化一次，PPO 更新时再做一次，导致概率分布前后不一致；
> GAE 漏掉最后一步；`train.py` 的切片错误让每次更新只有一条样本，而且异常被吞掉，最后保存的是
> 一个根本没训练过的模型；`data_generator` 调用了环境里不存在的方法。
>
> 我的重写版把这些问题全部修掉：4 条规则都做了语义等价的论证和单元测试，状态编码显式枚举
> 门/比特/时隙并加入空闲通道，动作掩码由规则适用性生成，网络只输出 logits、全局只做一次
> masked log-softmax，PPO 的 GAE 包含最后一步和 bootstrap，训练脚本用固定种子、多环境采集、
> 小批量多轮更新，评估输出 noop/random/greedy/agent 四种方法的压缩率、等价率和规则使用分布。
> 实验部分见文档，谢谢老师。

### 3.1 如果只有 1 分钟

抓住“三个正确性”：

1. **语义正确**：规则等价（模全局相位），测试与模拟器验证；
2. **训练正确**：概率只归一化一次（logits → masked log-softmax），GAE 含最后一步，切片正确；
3. **评估正确**：有基线、有压缩率、有等价率、有固定种子。

## 4. 为什么这样设计（答辩追问的核心）

### 4.1 为什么用 PPO？

| 候选 | 优点 | 缺点/为什么不用 |
| --- | --- | --- |
| **PPO（选用）** | on-policy、裁剪目标稳定、实现简单、支持离散大动作空间、可与掩码/优势估计自然结合 | 样本利用率不如 off-policy；但在本任务采集成本低、训练轮数少，可接受 |
| A2C/A3C | 更简单 | 每批数据只用一次，方差大、收敛慢；没有信赖域约束 |
| TRPO | 理论保证更强 | 需要二阶优化/共轭梯度，实现复杂，超参难调 |
| DQN 系 | off-policy、样本效率高 | 300 维离散动作上需要 `max_a Q(s,a)`，与动作掩码结合麻烦；价值过高估计；不直接输出策略分布 |
| SAC/DDPG | 连续控制强 | 本任务动作为离散；且策略需要显式分布与掩码 |

**要点**：本任务的动作空间是“离散 + 大量非法动作 + 状态可完全观测”，PPO 的“策略分布 + 裁剪”
与动作掩码是天然搭配；并且 PPO 的实现相对短，适合毕业设计讲清楚。

### 4.2 为什么必须有动作掩码？

- 300 个动作里，大部分在当前电路上无意义（规则不适用、比特不对、时隙越界）；
- 不掩码 → 大量概率浪费在非法动作上，采样到非法动作后只能重采样，`log_prob` 与采样分布不一致；
- 掩码后策略只在可行动作上归一化，PPO 的 ratio 有确切意义；
- 实现：`masked_log_softmax` 在 logits 上把非法位置设为 `-1e9`，归一化一次；
  熵也只对有效动作计算（`where` 避免 `0·(-inf)=nan`）。

**答辩金句**：“掩码不是为了‘过滤’，而是为了让策略分布与合法动作集合从定义上就一致。”

### 4.3 如何保证重写不改变电路语义？

1. **逐规则证明**（`docs/design.md` §5）：合并 = 同一比特上相邻门相乘（其它比特对易）；
   抵消 = 自逆门 `G²=I`；移动 = 只跨越不触及该门比特的层（对易），且保持每个比特上的顺序；
2. **模全局相位**：只要求 `U(C') = e^{iφ}U(C)`，因为全局相位不可观测，也是量子电路等价的标准定义；
3. **测试**：随机 200 个电路 × 4 条规则，只要 `is_applicable` 为真，就断言
   `circuits_equivalent(old, new) == True` 且 `cost` 严格下降；评估时每个电路再查一次
   `circuits_equivalent(initial, final)`，等价率应为 1.0；
4. **模拟器交叉验证**：可选的 cirq 对照测试，确保 numpy 模拟器本身没算错。

> 补充（如果老师追问“全局相位在受控时会不会有影响”）：本系统把整条电路作为独立执行对象，
> 全局相位对测量结果和黑盒行为不可观测；如果要把优化后的电路作为受控子程序嵌入更大电路，
> 则需要更严格的相位跟踪，这是可以扩展的方向（在局限中说明）。

### 4.4 为什么奖励设计成“势函数/压缩比例”，而不是 `−cost`？

- 原仓库用 `−depth − 0.2·门数` 的绝对负值：加门越走越差，最优策略是“不动”，且不同电路不可比；
- 本设计 `r_t=(C_t−C_{t+1})/C_0`：每一步只要行动就为正；按未折扣求和恰好是
  `(C_0−C_T)/C_0`（压缩比例），与电路规模无关；数值有界；
- 这属于势函数塑形的离散形式；γ=0.99 且回合 ≤48 步，折扣对排序影响小；
  最终评估直接看代价压缩率，不依赖回报数值。

### 4.5 为什么网络用 CNN？为什么输入是 `[14,Q,M]`？

- 电路天然是“比特 × 时隙”的二维网格，相邻比特/相邻时隙有局部结构，卷积参数共享、平移等变；
- 14 个通道把“门的类型 + 二比特门的角色 + 空闲”显式编码，状态对策略是充分（可还原电路）；
- 不用 MLP：参数量随 `Q·M` 爆炸且丢失局部性；不用 RNN：时隙顺序由张量第二维直接表达；
- 不用 BatchNorm：PPO 采样/更新分布持续变化，小批量下 BN 统计量不稳定，且训练/推理行为不一致；
  改用与批大小无关的 GroupNorm + ELU（每个卷积后都接）。
- 网络规模：默认 `H=64` 时约 392,165 个参数，CPU 毫秒级前向。
- 局限：3 层 3×3 卷积感受野 7×7，只覆盖 15 个时隙的一半——长程依赖是后续可改进点。

### 4.6 为什么是 4 条规则？会不会太少？

- 4 条规则覆盖了最典型的三类优化：门合并、门抵消、调度压缩（前后移）；每条都保证严格降代价；
- 动作空间 300，小到可以在 CPU 上训练、大到需要策略学习；
- 完备性确实有限（没有参数化旋转合并、三比特门等），这是明确的局限；
- 扩展方式：加规则 = 动作空间线性增长 + 规则实现 + 等价性测试，框架不需要改。

### 4.7 为什么用贪心/随机/不动作为基线？

- `noop`：验证“什么都不做”的零收益下界；
- `random`：验证“随机选可行动作”的探索基线；
- `greedy`：一步贪心，是强基线，用来判断 agent 是否真的学到了“多步/非短视”的收益；
- `agent`：确定性策略评估；
- 这四种方法用同一环境、同一规则、同一评估集，保证可比。

### 4.8 为什么用 CPU？

- 网络约 39 万参数、每轮 128 条样本、5 比特电路，CPU 足够；
- 降低复现门槛：没有 CUDA 的机器也能完整跑通（`--device cpu`，`--device auto` 可选 GPU）；
- 这也意味着实验重点在“方法正确性”而不是算力堆叠。

## 5. 实验怎么读（答辩现场看表指南）

### 5.1 指标定义

| 指标 | 定义 | 期望 |
| --- | --- | --- |
| 门数压缩率 `gate_reduction_pct` | `(initial_ops − final_ops)/initial_ops × 100%` | 越高越好 |
| 深度压缩率 `depth_reduction_pct` | `(initial_depth − final_depth)/initial_depth × 100%` | 越高越好；稠密随机电路上通常低于门数压缩率 |
| 代价压缩率 `cost_reduction_pct` | `(C_init − C_final)/C_init × 100%` | 越高越好，主指标 |
| 等价率 `equivalence_rate` | 保持幺正等价（模全局相位）的电路占比 | **必须 = 1.0**；低于 1 即正确性 bug |
| 平均步数 `mean_steps` | 每回合规约步数 | 与截断率一起看；过多说明策略绕路 |
| 截断率 `truncation_rate` | 因 `max_steps` 截断的回合占比 | 越低越好；高说明 `max_steps` 不够或策略低效 |
| 规则使用分布 `mean_rule_counts` | merge/cancel/move_earlier/move_later 的调用次数 | 反映策略学到什么；原仓库这类统计完全没有 |

### 5.2 典型解读（实验完成后补数字）

1. **先看等价率**：只要不是 1.0，后面数字都不可信——说明规则或模拟器有 bug。
2. **比较代价压缩率**：`agent > random` 是最低要求；`agent` 与 `greedy` 接近或超过是理想结果；
   `noop` 必须为 0。
3. **看门数 vs 深度**：随机稠密电路里 `merge`/`cancel` 主要降门数；`move_*` 要求“门独占一层”，
   触发较少，所以深度压缩率通常明显低于门数压缩率。这是可以解释的现象，不是失败。
4. **看规则使用分布**：如果 agent 几乎只用 `merge`，说明策略找到了主要收益来源；
   如果 `move` 使用极少，回到第 4.6 的规则适用性讨论。
5. **看训练曲线**：`mean_return` 上升、`explained_variance` 上升、`approx_kl` 在 0.02 以内、
   `entropy` 缓慢下降；若 KL 频繁超阈值或熵塌缩，说明更新过猛/探索不足。
6. **看截断率**：高截断率说明回合没走完就停了，可能需要增大 `max_steps` 或检查掩码是否过早全 False。
7. **random 有时也有收益**：因为随机也能命中可行动作；关键是 agent 应稳定优于 random。

### 5.3 如果实验效果不理想，怎么解释（提前准备）

- **agent ≈ greedy**：贪心在这个小规则集上是强基线，RL 的目标是学习近似最优的通用策略；
  可以展示 agent 在训练中逼近 greedy 的曲线，说明学习有效；
- **depth 压缩低**：规则设计导致（move 需独占层），并给出改进方向（更多调度规则/更稀疏电路）；
- **训练不稳定**：给 KL/熵/explained variance 曲线，说明监控到位；这是 PPO 调参的正常部分；
- **agent 不如 greedy**：诚实报告，并分析原因（规则集小、贪心接近最优、样本量/训练轮数）；
  强调本工作的第一目标是“正确、可复现的框架”，性能提升是后续工作。
- **不要做的事**：不要只报最好的随机种子、不要隐藏失败基线、不要修改等价率定义。

## 7. 局限与展望（必须能说 2–3 条）

1. **规则集不完备**：只有 4 类离散门的等价重写；不带参数化旋转角合并、三比特门、测量/重置；
2. **策略局部视野**：3 层 3×3 卷积感受野 7×7，对长程依赖（跨很多时隙的配对）不敏感；
3. **稠密随机电路上调度类规则触发少**：`move_*` 要求门独占时隙，深度压缩率受限；
4. **固定规模训练**：5 比特、深度 12；换规模/换分布需要重新训练或做结构适配；
5. **没有建模真实硬件**：无耦合图/噪声/保真度约束；
6. **未与工业转译器（Qiskit/TKet）全面对比**：基线是 noop/random/greedy，足以验证学习有效性，
   但不足以宣称 SOTA。

**展望**（挑 2–3 个说）：

- 规则扩展：参数化门角度合并、交换/重排类规则、三比特门；动作空间用分层/因子化策略降维；
- 网络扩展：空洞卷积/注意力/GNN 捕捉长程结构；图神经网络直接建模耦合图；
- 训练扩展：课程学习（由浅入深）、多规模混合训练、与搜索/贪心混合（RL 做决策、规则做约束）；
- 评估扩展：Qiskit/TKet pass 对比、真实设备噪声模型、更大规模 benchmark；
- 理论扩展：严格的势函数塑形（γΦ(s')−Φ(s)）与策略不变性证明、等价性从模全局相位到严格相位跟踪。

## 8. 可能被问到的问题与参考回答

> 回答策略：先给一句结论，再用 2–3 句展开；不会的不要编，明确说“这是后续工作/需要核实”。

**Q1：你的系统和 Qiskit/TKet 的优化 pass 有什么区别？**
A：Qiskit/TKet 是成熟的规则化转译器，内置大量优化 pass；本工作是用 RL 学习“在什么位置选哪条规则”的
策略，研究的是“决策”而不是“规则本身”。基线里 greedy 可以类比为“一步规则贪心”，agent 是要学习
比贪心更聪明的多步决策。当前规模下我们不自称超越工业转译器，重点是给出一个正确、可复现的 RL 框架。

**Q2：强化学习在这里真的有必要吗？贪心不行吗？**
A：贪心只挑“一步之后代价最小”的动作，容易陷入局部最优；RL 可以看多步回报（γ/GAE），
在规则组合有顺序依赖时可能更优。本设计把 greedy 作为强基线，实验会如实展示 agent 与它的差距；
如果差距小，说明在小规则集上贪心已接近最优，这本身也是有价值的结论。

**Q3：为什么动作空间是 300？会不会太大？**
A：`4 规则 × 5 比特 × 15 时隙 = 300`。不算大；而且掩码后每步通常只有十几个到几十个合法动作，
网络输出 `[B,4,5,15]`、一次 masked log-softmax 即可。相比“逐门合成”的动作空间，300 已经很小。

**Q4：掩码是否会让策略无法探索？**
A：掩码只屏蔽“在该状态下无定义”的动作，合法动作集合本身仍然包含多条规则、多个位置可选；
探索体现在合法动作上的 Categorical 采样与熵正则。屏蔽非法动作不会减少“有意义”的探索，
反而避免把探索浪费在不可能的动作上。

**Q5：为什么状态用张量，不直接用电路对象/图？**
A：张量让 CNN 可以直接处理，形状固定、可批量化；而且 `[C,Q,M]` 是电路的无损编码（门、时隙、二比特门角色都在）。
电路对象更适合规则层实现，不适合作为网络输入。GNN 是更自然的备选，但实现成本高，留作展望。

**Q6：14 个通道分别是什么？**
A：11 个门各一个 one-hot 通道（二比特门在两个比特上同时标记），加 control、target 两个通道表示
二比特门的角色，加 idle 通道表示“该比特该时隙空闲”；超出实际深度的时隙全部标记 idle，保证形状固定。

**Q7：为什么网络里不能先 softmax？**
A：因为 softmax 只能做一次，而且必须在“完整动作空间 + 掩码”上做。网络输出 logits，`masked_log_softmax`
负责唯一的归一化；如果网络先 softmax，上层再归一化/再做 softmax，采样分布、`old_log_prob`、`new_log_prob`
就会不一致，PPO 的 ratio 失效。原仓库正是这个错误。

**Q8：PPO 的 clip 为什么有效？**
A：ratio 偏离 1 太多说明新策略离旧策略太远；clip 后超过 `[1−ε,1+ε]` 的部分不再提供梯度，
从而限制单次更新幅度（信赖域近似），避免策略崩溃。配合多 epoch 更新和 KL 早停更稳。

**Q9：GAE 是什么？为什么 λ=0.95？**
A：GAE 用 `δ_t` 的指数加权和估计优势：λ=0 退化为单步 TD（低方差高偏差），λ=1 退化为蒙特卡洛
（高方差低偏差）；0.95 是常用折中。实现上必须包含最后一步并用 bootstrap 价值处理截断。

**Q10：奖励为什么用 C_0 归一化？**
A：不同电路规模不同，绝对代价不可比；除以初始代价后奖励无量纲、有界、每步为正，
且未折扣总回报就等于“压缩比例”，解释性强，也让不同回合的回报可比。

**Q11：等价性为什么允许全局相位？**
A：量子态/幺正矩阵的全局相位不可观测，测量概率与黑盒行为都不变，这是量子电路等价的标准定义；
测试用 `circuits_equivalent` 比较两个电路的幺正矩阵在模全局相位下是否一致。若未来要把电路作为
受控子程序嵌入更大电路，可以扩展为严格相位跟踪（见局限）。

**Q12：如果规则应用后电路不合法怎么办？**
A：规则实现内部保证：合并/抵消只删除或替换门；移动把门放进“与其比特不相交的层”，不会造成同层
比特冲突；构造 `Circuit` 时会再次校验并丢弃空层。测试会对每条规则的输出检查合法性。

**Q13：训练怎么判断收敛/健康？**
A：看 `train_log.csv`：`mean_return` 上升、`mean_final_cost` 下降、`explained_variance` 上升、
`approx_kl` 不频繁超 `target_kl`、`entropy` 缓慢下降而不塌缩、`clip_fraction` 不高；
评估集 `eval_log.csv` 的 `cost_reduction_pct` 稳定上升。

**Q14：如果训练不收敛，你会怎么排查？**
A：先看等价率/环境断言（正确性）→ 再看掩码是否过早全 False（截断率）→ 再看 reward 曲线是否上升
→ 看 KL/熵/值函数 explained variance 判断更新是否过猛/价值学不到 → 调 lr、entropy_coef、
update_epochs、minibatch、训练电路分布。仓库里保留了完整日志与可复现配置。

**Q15：数据集多大？会不会过拟合？**
A：训练用随机生成（默认 200 个，seed=0），评估用另外 100 个（seed=10000）或固定 `data/eval.json`；
训练/评估种子不同，避免泄漏。网络是策略网络而不是分类器，过拟合主要表现为对训练电路分布过拟合，
评估集就是检验泛化。数据规模小是毕业设计的限制，可通过增大 `train_circuits` 扩展。

**Q16：为什么不用 GPU / 为什么训练这么快？**
A：网络约 39 万参数、每轮 128 条样本、5 比特电路，CPU 足够；不依赖 CUDA 让复现门槛更低。
有 GPU 时可传 `--device cuda`（环境不支持会自动回退 CPU）。

**Q17：为什么原仓库的代码会“看起来能跑”？**
A：`train.py` 用 `except Exception` 把每个 epoch 的错误都吞掉，然后打印 “Epoch complete”，
最后照常保存模型。实际上第一次 `PPO.update` 就因为切片把 batch 维弄丢、Conv2d 要求 4 维输入而报错，
所以保存的是随机初始化模型。`evaluate.py` 又复用了坏掉的采样器，只打印一个负奖励总和。
详见 `PROBLEM_ANALYSIS.md` §2.6、§4。

**Q18：你的工作量和创新点怎么体现？**
A：工作量：从零重写 18 个模块（门库/电路/模拟器/观测/生成器/动作/规则/掩码/环境/网络/PPO/采样/训练器/基线/评估/可视化/工具）、
4 个 CLI 脚本、16 个测试文件（237 passed，含独立审计 55 个用例）、完整文档与实验流水线；创新点/价值：把不可运行、语义错误、概率错误的原型
修正为正确可复现的系统，并引入势函数奖励、动作掩码、等价性审计、完整评估协议；同时给出原仓库逐文件缺陷分析
（`PROBLEM_ANALYSIS.md`），这对后续同学有参考价值。

**Q19：为什么不用 AlphaZero/MCTS？**
A：MCTS 需要可模拟的搜索树与大量模拟，本任务的转移确定、动作空间 300，MCTS 可行但计算与实现成本高；
PPO 更简单、可直接在掩码动作空间上训练，适合毕业设计范围。可以把 MCTS 作为后续对比方向。

**Q20：如果老师问“量子电路优化里 RL 的 SOTA 是什么”，怎么答？**
A：相关研究主要集中在量子比特映射/路由、转译 pass 选择、电路合成等方向（具体文献答辩前按参考文献核实）。
本工作不是追求 SOTA，而是完成一个“MDP 建模 + 等价重写规则 + 掩码 PPO + 可复现评估”的完整闭环；
与工业转译器的全面对比是后续工作（见局限）。

**Q21：你的代码怎么证明是对的？**
A：三层证据：① 单元测试（16 个测试文件、237 项，覆盖门/电路/模拟器/规则/掩码/环境/网络/PPO/采样/训练器/评估/脚本）；
② 规则随机测试（200 电路 × 4 规则，验证等价 + 严格降代价）；③ 独立审计（`tests/test_audit.py` 55 个对抗性用例，
独立参考实现交叉验证；报告见 `docs/audit-report.md`，结论 P0=0、P1 已修复）。
实验中的等价率必须为 1.0。

**Q22：为什么 `n_moments=15`？电路优化变浅后状态怎么办？**
A：初始深度 12，留 3 格余量；观测张量形状固定，比实际深度多出的时隙标记为 idle；优化后电路变浅，
多出来的时隙仍是 idle，编码不变，网络无需重新适配。

**Q23：如果动作全被掩码，环境会怎样？**
A：`done=True`（terminated），回合结束；`RolloutCollector` 记录 `dones=1` 并 auto-reset 新电路。
不会出现“没有动作可采”的死锁。

**Q24：为什么 `max_steps=48`？**
A：初始代价约 `55 + 0.5×12 ≈ 61`，每步至少降 0.5，理论回合长度上界远大于 48；48 是训练/评估
的时间上界，防止策略绕路。截断率作为指标监控；若过高再调。

**Q25：为什么用 `λ=0.5` 作为深度权重？**
A：深度通常比门数更“贵”（执行时间），0.5 是一个折中；它也决定 move 规则的每步收益
（`−λ/C_0`）。可通过 `--lambda-depth` 调参，实验中可作为超参分析。
